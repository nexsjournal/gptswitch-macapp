# 产品需求规格

关联：[调研](research/01-reference-projects.md) · [能力边界](research/02-codex-feasibility.md) · [页面设计](design/04-pages-and-flows.md)

## 1. 产品定位

面向已经使用 Codex Desktop、拥有自定义 API 服务商或中转 API Key 的个人开发者。提供本地、可解释、可恢复的配置管理。Codex 继续承担对话、文件操作、工具执行和任务历史；Switchelp 负责供应商、凭据、模型能力、连接诊断与配置应用。

用户说的“右下角模型”指 Codex 输入区附近的原生模型选择器，不是本工具自己的模型列表，也不是悬浮窗。界面位置会随 Codex 版本变化，验收以该选择器的真实行为为准。

核心价值是：用户知道自己选了谁、下一次请求去哪里、哪些能力真能用、失败怎么恢复。

## 2. 用户问题与产品响应

| 用户问题 | 本项目要求 |
| --- | --- |
| 供应商配置后还要来回校准 | 一次应用事务汇总所有必要步骤，展示明确阶段和结果，不循环修复 |
| Key 多了难管理 | 每个供应商独立管理多 Key，备注、固定选择、检测、替换、禁用 |
| 模型不在自动发现列表 | 始终允许手动输入精确模型 ID；模型发现不是保存前置条件 |
| 不知道是否连接成功 | 分开显示网关、认证、模型调用、工具调用、Desktop 加载状态 |
| 无法修改上下文和输出 | 独立模型编辑器，区分发布上限、用户上限、网关约束和 Codex 有效窗口 |
| 图片、视频、PDF 能力不清楚 | 按输入类别记录原生、转换后、未知、不支持，并标出接入链路限制 |
| 思考档位不适配 | 每模型独立档位和参数映射；未知时不凭空补齐 low / medium / high |
| 想保留 Codex 使用习惯 | 原生选择器、原生历史、原生工具执行；不另造聊天工作台 |
| macOS / Windows 都要用 | 共享核心与界面，两平台分别完成接入和恢复验证 |

## 3. 范围与优先级

### P0：首次可用版本必须包含

- 供应商增删改、搜索；自定义 URL；预设以填表辅助方式提供，不能绑定推荐或充值。
- 每供应商多个 API Key；默认固定当前 Key；新增、替换、禁用、检测；系统凭据库保存。
- 从 `/models` 发现模型以及手动新增；精确保留 ID 大小写、斜杠和 Unicode。
- 独立模型编辑：显示名、上游 ID、协议、上下文、输出限制、输入能力、工具能力、推理档位。
- Codex 接入检测、配置差异预览、一次应用、失败恢复、还原上次配置。
- 模型在受支持版本的 Codex 原生选择器可见，选中后走对应服务商和 Key。
- Responses 原生兼容路径；Chat Completions 适配通过工具调用门禁后进入首发，未通过则明确标实验状态，不能冒充完整可用。
- 分阶段连接测试、脱敏日志、配置备份；桌面托盘/菜单栏；关闭窗口后可继续代理。
- macOS Apple Silicon 与 Windows x64 的签名安装包及相同核心功能。

能力字段的编辑与展示都属于 P0；不代表 PDF、视频原生传入 Codex 也属于 P0。当前链路不能执行的能力必须可见但不可启用，并解释原因。

### P1：基础链路稳定后

- 受约束的同供应商 Key 故障切换；不跨供应商自动发送内容。
- 批量模型编辑、配置模板、加密导入导出、托盘快捷启用。
- Anthropic Messages 等独立协议适配，按真实工具测试逐个开放。
- 官方订阅模型与自定义模型同一菜单共存的 Desktop Bridge，须通过独立兼容门禁。
- macOS Intel 支持，以目标 Codex 可用版本为前提；Windows ARM64 单独评估。
- 在宿主确实传递相应附件时，加入显式 PDF 转换/图像降级策略。

### 当前不做

官方账号轮换、OAuth 订阅导入、语音栏、GPT-Live、子智能体调度、会话迁移/删除、插件市场、远程控制、局域网网关、云同步、平台充值与价格商城。参考产品存在这些功能，不构成本项目范围。

当前范围未包含内嵌浏览器；供应商官网、帮助等链接默认交给系统浏览器。若后续明确需要高频内嵌控制台、多标签、独立网页登录会话，应在 G1 前按 [桌面壳复审](research/03-desktop-shell-decision.md) 调整技术选型、验收和工期。模型的图像/视频/PDF 能力配置不等于本工具需要内置浏览器。

## 4. 关键用户故事

### US-01：添加第一家供应商

1. 检测 Codex 安装位置、版本、实际配置根目录与冲突工具。
2. 用户填名称、Base URL、API Key；选择协议或接受可见的预设。
3. 可点击“获取模型”，也可直接“手动添加模型”。
4. 选中模型，在能力编辑器检查参数；未知能力保持未知。
5. 点击“测试并应用”，查看将修改的范围；执行后显示“已加载”或“等待 Codex 重新加载”。
6. 在 Codex 新任务中选中模型，受控测试或下一次真实请求确认实际路由。

保存不会偷偷重启 Codex。应用前的差异页就是最终确认界面，不能再弹三次同义确认。

### US-02：更换 Key

同一供应商、相同模型和权限范围，选择另一 Key。新请求使用新 Key；已在途的请求和依赖服务端响应 ID 的续接维持原凭据。UI 明示“后续新请求使用”，不写“所有会话已切换”。如需要清空续接，新建任务比偷偷换路由更可预测。

### US-03：调整自定义模型

模型编辑器中填写有效上下文和最大输出 Token；配置推理档位及默认值。保存后展示字段的生效位置。网关参数与目录参数分别标明立即应用或需重载，统一进入待应用清单。

### US-04：失败时继续工作

应用失败保持旧运行快照；如果已写文件则根据事务日志恢复受管理字段。若用户同时手改了配置，保留其改动并进入冲突处理。提供“使用上次可用配置”与“恢复原生模式”。禁止自动删除 Codex 历史、认证和缓存来碰运气。

## 5. 功能边界定义

| 术语 | 定义 |
| --- | --- |
| 供应商 | 用户管理的独立连接实例；同一厂商可有多个 URL 或环境 |
| 模型 | 供应商实例中的可调用模型及能力版本 |
| Key 可用 | 在指定时间、接口、模型上认证成功；不代表所有模型都有权限 |
| 已保存 | 元数据和密钥引用持久化完成 |
| 已应用 | 本机网关已装载指定版本，必要配置已提交 |
| 已加载 | 受管 Codex 实例读到了对应模型目录；不能由保存动作推断 |
| 已验证路由 | 特定请求实际匹配预期供应商、模型和凭据版本 |
| 恢复原生 | 撤销本工具接管的配置与启动入口；不是清空用户所有自定义设置 |

## 6. 非功能目标

下列均为未来验收目标，尚无实测数据。

| 指标 | 目标与测量条件 |
| --- | --- |
| 切换 Key / 发布请求策略 | 本机提交到新请求可见 p95 ≤ 300 ms，不计上游响应 |
| 网关附加延迟 | 同机同上游、预热连接、100 次文本请求，首字节增量 p95 ≤ 30 ms |
| 配置安全 | 中断任何写入阶段都可恢复；未管理字段语义、注释和换行保留 |
| 首次打开 | 参考设备本地冷启动 p95 ≤ 2 s；后台检查不阻塞窗口 |
| 资源预算 | 窗口关闭且无请求时核心常驻内存目标 ≤ 80 MB；含窗口总内存目标 ≤ 180 MB，需分 OS 实测 |
| 可理解性 | 新用户不编辑 TOML 即可完成添加、检测、应用、恢复 |
| 可访问性 | 正文 AA 对比度，完整键盘操作，读屏状态反馈，支持 200% 缩放 |
| 隐私 | 默认不上传遥测、不记录请求正文、不导出密钥 |

## 7. 发布验收

任一核心条件未达成不得称“稳定版”：两个不同供应商的同名模型可区分；菜单选择与实际路由一致；上下文/输出/推理有可观测结果；图片能力不会虚报；外部配置冲突可恢复；双平台真实 Codex 验收完成。

“界面做好”“HTTP 200”“配置文件写入成功”均不是上述验收的替代物。
